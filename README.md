## اللعب مباشرةً
افتح رابط صفحة GitHub Pages للعبة. اللعب الفردي يعمل من الصفحة. وللعب الجماعي مع صديق، يجب تشغيل خادم Node.js عام عبر HTTPS/WSS، ثم إدخال عنوان الخادم في نافذة «لعب شبكي». GitHub Pages يستضيف ملفات اللعبة فقط ولا يشغّل خادم Socket.IO.

## تشغيل الخادم محليًا
1. ثبّت Node.js 20 أو أحدث.
2. افتح مجلد `server` وانسخ `.env.example` إلى `.env`.
3. غيّر `SESSION_SECRET` إلى سر عشوائي طويل.
4. نفّذ `npm install` ثم `npm start`.
5. افتح `http://localhost:3000`؛ الصديق على شبكة المنزل نفسها يمكنه استخدام عنوان الجهاز المحلي.

## استضافة اللعب الجماعي عبر الإنترنت
ارفع مجلد المشروع إلى خدمة استضافة Node.js تدعم WebSocket. اضبط أمر البناء `npm install` وأمر التشغيل `npm start` ومجلد الجذر `server`. اضبط `SESSION_SECRET` بسر ثابت طويل، و`CLIENT_ORIGIN` على نطاق صفحة اللعبة. بعد النشر، أدخل عنوان الخدمة `https://...` داخل نافذة اللعب الشبكي. لا تنشر ملف `.env` أو سر الجلسة.

**حالة النشر:** ملفات اللعبة والخادم جاهزة في المستودع. صفحة GitHub Pages ثابتة؛ خادم اللعب الجماعي العام يحتاج نشرًا منفصلًا على خدمة Node.js، ولم يُنشأ له عنوان عام في هذه النسخة.

## فريق غارة الزعماء
من واجهة «لعب شبكي» اختر «إنشاء فريق» وشارك رمز الفريق بصديقين، أو استخدم «ابحث عن فريق». يختار قائد الفريق درجة الصعوبة من 1 إلى 5، ويبدأ اللعب عندما يصبح الأعضاء الثلاثة جاهزين. تُعاد حالة الفريق بعد انقطاع قصير؛ وتُحفظ مكافآت الفوز في ملف اللاعب على الخادم. إعداد التصميم والتفاصيل موجود في `docs/ORIGINAL_IP_DESIGN_AR.md`.

لفحص قواعد الخادم محليًا، من مجلد `server` شغّل `npm test` ثم `npm run check`. جرّب تدفق الفريق بفتح ثلاث جلسات متصفح على الخادم نفسه.

## التفاصيل
- الحساب الشبكي ضيف؛ بياناته تحفظ على خادم واحد.
- مباريات الإقصاء الحالية مستقلة عن غرف التعاون؛ لا تتغير قواعد PvP عند إنشاء فريق.
- الأصول والرسوم والصوت في الملف المدمج؛ لا تعتمد المؤثرات الجديدة على ملفات خارجية.
